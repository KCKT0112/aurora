# Unix/Linux 设计方向

继承成熟的接口和分层思想：UID/GID与凭据继承、属主/组/mode、最小权限、文件描述符、进程生命周期、稳定用户态ABI、可组合终端工具、可诊断错误、明确资源所有权及可回收生命周期。

微内核是当前架构约束。Linux的进程和文件语义可以在独立用户态服务中实现，无需把文件系统、驱动策略或图形服务重新塞回ring0。Aurora不是Linux内核分支，也没有Linux二进制兼容性；目前使用自己的syscall和IPC ABI，不能直接运行Linux ELF。

## 已落实

- 独立用户地址空间、RX/RW+NX、用户指针检查、ELF版本协议。
- 不可变进程UID/GID、root与普通账号、密码认证、注销和会话回收。
- 文件owner/group/other判定、目录搜索权限、sticky目录、stat/chmod。
- 受限进程控制、系统信息、阻塞等待和消息唤醒。
- 服务和应用与内核独立构建；系统目录和启动包有固定位置。

## 下一步顺序

1. **统一文件接口**：open/read/write/close/lseek/stat，按进程分配fd，打开时确定权限并定义撤销语义；目录迭代与路径处理独立于GUI预览协议。
2. **进程执行与继承**：spawn/exec/wait、退出状态、父子关系、凭据与fd继承、终端会话；定义信号/取消语义。是否提供fork取决于地址空间复制/COW能力。
3. **持久化**：用户态块设备服务、VFS挂载、持久化文件系统、fsync与崩溃恢复；账号/配置写入使用原子替换。
4. **身份细化**：专用服务账号、附加组、受控提权、umask、chown、账号管理；在可信认证边界内处理真实/有效/保存UID。
5. **兼容层**：先明确POSIX子集，再考虑libc移植与源码兼容；不提前承诺Linux syscall二进制兼容。

当前 `/system` 承载不可变系统包，`/etc`、`/home`、`/root`、`/tmp`、`/var`、`/run` 遵循Unix职责。将来提供 `/bin`、`/sbin`、`/usr`、`/lib` 等标准入口时应使用受验证的符号链接或挂载别名，同时完成路径解析规则。现在不创建没有执行/动态链接功能的伪入口来声称FHS兼容。

内核更新沿用独立ABI、兼容验证、可回滚重启升级。完整内核热切换、Linux livepatch和kexec是不同能力；不会把其中一种当成另一种已经完成。
