# 驱动加载与系统更新设计

## 当前已完成的基础

内核和用户程序为独立 ELF；系统与应用有版本化 ABI。Limine 加载独立模块，init 通过受限 SYS_SPAWN 启动，镜像通过 W^X、ABI note 和边界验证。内核更新可以替换 ISO 中 `/system/kernel/aurora.elf`，兼容的用户 ELF 无需重链，但仍需重新启动。源码 `make kernel` 不依赖用户 ELF。

input 用户态模块安装在 `/system/drivers/input.elf`，但其硬件端口访问与 virtio 队列机制仍由内核提供。系统尚未实现任意用户态驱动动态安装、卸载、设备发现订阅或热插拔。把新的 ELF 放进目录不会自动执行，也不会获得设备权限。

## 驱动包规范（目标，尚未实现）

包使用反向域名 ID，manifest 至少包含 schema version、驱动 ID/version、目标架构、最低/最高 driver ABI、入口 ELF、设备匹配项、所需 IRQ/MMIO/DMA 权限、资源配额、更新兼容性、内容哈希与发布者签名。默认权限为空。

安装包位于 `/var/lib/packages/<id>/<version>/`，采用临时解包、完整验证、原子激活；不可直接覆盖正在运行的文件。driver manager 根据管理员策略批准设备绑定，内核创建受限对象句柄；匹配设备不等于自动授权。原始物理内存、全端口 I/O、任意 PCI config 写入不应向普通驱动开放。

加载顺序：验证签名/哈希/ABI → 资源配额 → 创建隔离地址空间 → 分配设备句柄 → 初始化握手 → 发布服务。卸载先拒绝新请求，再 drain I/O、屏蔽 IRQ、停止 DMA、撤销映射与句柄，最后回收地址空间。没有 IOMMU/可靠 DMA 停止机制的设备不承诺安全热卸载。

首批目标为 virtio block、virtio sound/gpu/input，避免在基础机制不全时同时铺开 USB、网络和所有真机驱动。当前已验证PC speaker通知音和AC97 PCM-out；AC97为过渡内核机制，用户态驱动隔离仍未完成。

## 更新分层

| 更新方式 | 当前状态 | 必要条件 |
|---|---|---|
| 独立重建/替换内核文件后重启 | 基础已具备 | ABI 匹配，新的启动镜像验证 |
| 普通应用结束并重新启动 | 已实现 | 内存回收、端点重新发现；应用状态会丢失 |
| 系统服务无感替换 | 未实现 | supervision、状态 schema、请求 drain、连接恢复 |
| 小范围内核 live patch | 未实现 | 安全点、代码替换/撤销、栈和符号约束 |
| 运行中替换整个内核并保留会话 | 未实现 | CPU/内存/设备状态交接、原子切换、失败回滚 |

Linux 的 livepatch 通常修补有限函数，kexec 则进入新内核；二者都不等于任意完整内核无中断更换。Aurora 先保证稳定 ABI 和可回滚重启升级，再做用户态服务更新，最后评估内核切换可行性。

完整内核切换至少需要：版本化 handover record、跨内核内存所有权、线程寄存器/等待状态、IPC/能力代际、IRQ/DMA 安全停机、计时器重建、设备重新绑定、并发 CPU 同步以及旧内核回滚。当前任何一个核心条件都不完整，因此不提供伪装成“热更新”的直接跳转入口。

## 升级验证门槛

兼容版本可启动旧用户程序；不兼容版本在加载前明确拒绝。更新失败要保持已安装版本可启动。服务更新必须通过处理中断、未完成写事务、满队列、服务崩溃和设备超时测试。签名根、密钥轮换、离线恢复和 A/B boot slots 应与安装管理器一起设计。

接口演进遵循 [Unix/Linux设计方向](LINUX_DESIGN.md)，但保持用户态驱动与服务的微内核边界。多用户基础已完成，通用对象能力、驱动撤销与持久化仍未完成。
